## 1. 한 줄 요약

개인 기록 블로그로 시작해, **기획·개발·QA·운영 역량을 보여 주는 원페이지 포트폴리오 + 개발 기록(블로그)** 으로 바뀌는 중인 사이트입니다. 관리자는 GitHub 로그인 한 명이며, **홈 화면에서 바로 편집**하고 글은 **블로그형 에디터**로 씁니다. 모든 변경은 이슈 → PR → CI → 릴리스로 기록됩니다(이 과정 자체도 포트폴리오의 근거).

**푸터**: 기록 · 아카이브 · 태그 · 관리자(로그인) · 맨 위로

## 4. 포트폴리오 홈(`/`) 구성 — 위에서 아래로

1. **히어로(첫 화면)** — 제도 용지(격자) 위에 이름을 **네 색 펜(기획·개발·QA·운영)이 차례로 그린 뒤 먹으로 채움**. 마우스를 올리면 네 장의 레이어가 **3D로 벌어지며** 역할 이름표가 나타나고 포인터를 따라 기울어짐. CAD 십자선·좌표 커서. 하는 일 한 줄(태그라인)과 소개 문장. (터치·움직임 줄이기에서는 정지 상태)
2. **소개** — 표제란 형식의 인적 사항(이름·생년월일·위치·학력·이메일·GitHub). 빈 값은 표시하지 않음.
3. **일하는 방식** — 공개 커밋 기록(Conventional Commits 접두어)으로 계산한 역할 비율. 큰 숫자 4개 + 주별 누적 영역 차트(스크롤에 맞춰 그려짐). 현재: 개발 52 · 운영 35 · QA 10 · 기획 3(%). *스쿼시 병합 PR 제목 기준이라 기획이 실제보다 낮게 잡힘.*
4. **역량** — 분류별 범례(분류 앞에 역할 색 점). 역량을 누르면 프로젝트·경력이 그 역량으로 걸러지고 주소에 `?skill=`이 남음(View Transitions로 전환).
5. **코드와 기록** — GitHub, 기록(`/notes`) 바로가기 카드.
6. **프로젝트** — 대표 프로젝트는 **쇼케이스 블록**(큰 커버 + 프로젝트 강조색 프레임 + 소개 글 + 역할 비율 막대 + 성과 수치 + 핵심 결정 + 기술 태그 + 버튼), 나머지는 작은 카드. 커버가 없으면 강조색으로 표지를 자동 생성.
7. **경력** — 스크롤에 따라 세로선이 채워지는 타임라인. 회사별 프로젝트 연결.

## 5. 관리자

### 5-1. 로그인·권한
- 푸터 「관리자」 → GitHub 로그인. `admins` 허용 목록에 있는 GitHub 계정만 관리자.
- 권한은 세 겹: 화면(버튼 노출) → 서버 액션의 관리자 재확인 → DB의 RLS 정책.

### 5-2. 홈에서 바로 편집 (새 방식)
관리자로 로그인하면 홈 오른쪽 아래에 **「이 화면 편집하기」** 도구가 뜨고, 켜면 섹션마다 수정·추가 버튼과 입력창이 열립니다. 저장하면 공개 화면에 즉시 반영됩니다.

| 대상 | 편집할 수 있는 것 |
| --- | --- |
| 인적 사항 | 이름, 히어로에 그릴 이름(영문 권장), 하는 일 한 줄, 소개 문장, 생년월일, 위치, 학력, 이메일, GitHub 아이디 |
| 역량 | 이름+분류로 추가(주소용 slug 자동), 이름·분류·설명 수정, 삭제 |
| 프로젝트 | 이름, 한 줄 설명, 소개 글, 개인/회사(회사면 소속 경력), 맡은 일, 기간(월 선택), 인원, 대표 여부, 사내 기밀 표시, **커버 이미지 업로드**, 강조색(견본 8개+직접), 이미지 설명, **갤러리**, 성과 수치(줄 추가), 핵심 결정(줄 추가), 쓴 기술(칩 선택), **상세 소개(블로그형 에디터)**, 사이트 주소, GitHub 저장소·공개 여부, 삭제 |
| 경력 | 회사(기밀이면 공개용 표현), 직함, 기간, 요약, 주요 성과(줄 추가), 사내 기밀 표시, 삭제 |

### 5-3. 관리자 화면(`/admin`) — 예전 방식, 아직 사용 중
| 경로 | 화면 |
| --- | --- |
| `/admin` | 대시보드 — 글 상태 4종(초안·자동생성 대기·발행됨·실패) 필터, Realtime 실시간 갱신, 바로가기 위젯, API 사용량 |
| `/admin/posts/new`, `/admin/posts/[slug]` | 글 작성·편집 — **블로그형 에디터**(새 글), 예전 마크다운 글은 50:50 분할 편집. 분류·상태·출처·태그·요약·발행 시각(예약 발행), 자동 저장, AI 제안(요약·태그·제목 후보). 주소(slug)는 비우면 제목으로 자동 |
| `/admin/projects`, `/new`, `/[slug]` | 프로젝트 생성·연결 — GitHub 저장소 연결·동기화(README·커밋 최대 500·PR) |
| `/admin/projects/[slug]/summarize` | 프로젝트 커밋으로 개발 일지 초안 생성(AI, 스트리밍) |
| `/admin/videos` | 구독 채널 영상 훑기(YouTube 쿼터 표시) |
| `/admin/videos/[videoId]` | 영상 시청 + AI 요약 초안(자막 없으면 설명으로 대체) → 글로 저장 |
| `/admin/videos/channels` | 구독 채널 등록·해지, 쿼터 현황 |

### 5-4. 블로그형 에디터 (글·프로젝트 상세 공통)
- 도구 모음: 실행 취소/다시 · 문단 스타일(본문/제목1/제목2/작은 제목) · 글꼴(고딕/명조/고정폭) · 크기(13~34) · 굵게/기울임/밑줄/취소선 · 글자색(9색) · 정렬 · 글머리/번호 목록 · 인용 · 코드 블록 · 구분선 · 링크 · 이미지 · 파일 첨부 · 표(행·열 추가/삭제)
- 메뉴는 **실제 모양대로** 보이는 목록(글꼴은 그 글꼴로, 크기는 그 크기로).
- 이미지·파일은 버튼/끌어다 놓기/붙여넣기 → Storage(`media` 버킷, 10MB, 이미지·PDF·ZIP·오피스 문서) 업로드.
- 저장 형식: 에디터 문서(JSON). 공개 화면은 허용 목록에 있는 요소·스타일만 그림(XSS·CSS 주입 차단).

## 6. 데이터 모델 (Supabase `public`)

| 테이블 | 용도 | 공개 범위(RLS) |
| --- | --- | --- |
| `profile` | 인적 사항(한 행) | 누구나 읽기, 관리자만 쓰기 |
| `projects` | 프로젝트. 기본(이름·설명·저장소·상태) + 포트폴리오(종류·경력·역할·기간·인원·성과·결정·기밀·대표·순서) + 쇼케이스(소개 글·강조색·커버·갤러리) + 상세 본문(`story`) | 누구나 읽기 |
| `experiences` | 경력 | 누구나 읽기 |
| `skills` / `project_skills` | 역량 / 프로젝트↔역량 연결 | 누구나 읽기 |
| `posts` | 글. `doc`(에디터 문서) 또는 `body`(마크다운), 상태·예약 발행 | 발행됨 + 발행 시각이 지난 글만 |
| `repo_commits` · `repo_pulls` · `repo_readmes` | GitHub 캐시 | 저장소 공개로 표시한 프로젝트만 |
| `channels` | 구독 채널 | 누구나 읽기 |
| `api_usage_log` · `ai_models` · `ai_tasks` · `bookmarks` · `admins` | 운영용 | 관리자만 / `admins`는 아무도 |

- 새 테이블은 RLS에 더해 익명 사용자 권한을 **읽기로만** 좁힘(이중 방어). CI가 매번 공개 키로 쓰기·업로드가 막히는지 검사.
- 공개 화면의 DB 조회는 1시간 캐시, 관리자 저장 시 즉시 무효화.

### 현재 데이터 상태
- 인적 사항: **이름 비어 있음**(첫 화면에 "Portfolio"가 대신 그려짐), 태그라인 「기획 · 개발 · QA · 운영」
- 프로젝트 2개: `index-blog`(대표, 실제 내용·캡처·상세 소개 있음), `autopost`(이름·설명만)
- 경력 0개 · 역량 18개 · 공개 글 0편(검증용 행 2개만) · 업로드 파일 0개
- index-blog 커버 이미지는 **이전 디자인 화면 캡처**라 교체 필요

## 7. 디자인 시스템 (v0.4)

- **기본 밝은 테마**(다크는 토글). 차가운 흰 바탕, 각진 모서리·괘선의 "제도 도면" 언어, 프로젝트 쇼케이스만 둥근 모서리.
- **역할 색 4개**가 사이트 전체의 의미 체계: 기획(노랑) · 개발(울트라마린) · QA(민트) · 운영(핑크). 면(점·막대·영역·펜)에만 쓰고 글자는 본문 색.
- 강조색(링크·포커스·버튼): 울트라마린. 프로젝트마다 고유 강조색(커버 프레임·수치).
- 글꼴: Pretendard(본문·제목), JetBrains Mono(코드·좌표), Noto Serif KR(에디터 명조).
- 모션: 히어로 플로터·3D 레이어, 차트 스크롤 그리기, 경력 타임라인 채움, 필터 View Transitions. 모두 「움직임 줄이기」 존중.

## 8. 개발·운영 프로세스

- 이슈 → 브랜치(`type/번호-요지`) → PR(템플릿, 제목은 Conventional Commits 검사) → CI(lint·typecheck·unit·RLS 검사 → build·E2E) → Vercel 미리보기 → 스쿼시 병합 → release-please 릴리스 PR → 태그·CHANGELOG.
- main은 보호 브랜치(CI 통과 필수). 현재 v0.4.0.
- 문서: `CONTRIBUTING.md`, ADR 0001~0005(`docs/adr/`), `docs/ROADMAP.md`.

## 10. 알려진 한계

- 역할 비율은 PR 제목 기준이라 PR 안의 문서·테스트 작업이 묻힘(기획이 과소 집계).
- `/projects`(목록)와 홈 프로젝트 섹션이 따로 존재 — 역할이 겹침.
- `/notes`는 예전 블로그 홈 구성을 그대로 씀(새 디자인 언어와 덜 맞음).
- 관리자 기능이 「홈에서 편집」과 「/admin」 두 곳에 나뉘어 있음.
- 갤러리 이미지는 썸네일만 있고 크게 보기(라이트박스) 없음.
- Vercel 미리보기 주소에서는 로그인 리디렉션이 막힐 수 있어 편집은 운영 주소에서.
