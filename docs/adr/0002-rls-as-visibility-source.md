# 0002. 공개 범위는 앱이 아니라 RLS가 정한다

- 상태: 채택 (사후 기록)
- 날짜: 2026-10-12

## 맥락

글에는 초안·예약 발행·실패 상태가 있고, 공개 화면 질의는 여러 곳(홈·아카이브·태그·검색·404)에
흩어져 있습니다. 앱 코드에 `status = 'published'` 조건을 두면 한 곳만 빠뜨려도 초안이 새어 나갑니다.

## 결정

`posts`의 RLS 정책이 "발행됨 + 발행 시각이 지남"인 행만 공개 키에 보여 줍니다. 공개 화면의
데이터 계층 질의에는 상태 조건을 두지 않습니다.

## 대안

- 앱 계층의 공통 질의 함수로 강제 — 새 질의가 그 함수를 우회하면 끝납니다.
- 공개용 뷰 — RLS와 같은 효과지만 쓰기 경로와 정책이 둘로 갈라집니다.

## 결과

- 좋은 점: 예약 발행이 별도 작업 없이 시각이 되면 열립니다. 실수의 반경이 DB 한 곳으로 줄어듭니다.
- 감수하는 점: 정책이 틀리면 전부 틀립니다 — 그래서 `scripts/check-rls.mjs`로 공개 키 기준 검증을 둡니다.
